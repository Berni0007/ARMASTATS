# Архитектура

## Поток данных

1. Мод `ZarubaStats` работает только на сервере и цепляется к базовому `SCR_BaseGameMode`, поэтому подходит к любому сценарию.
2. События уходят на хост: `POST {apiUrl}/api/events`, тело JSON.
3. Сервис на хосте проверяет токен, сохраняет событие и обновляет статистику.
4. Discord-бот в том же процессе публикует отчёт матча и отвечает на `/stats`.

## Ограничения REST в Reforger

- Тело запроса меньше 1 МБ.
- Заголовки задаются одной строкой через `RestContext.SetHeaders`.
- Токен передаётся в теле запроса, а не в заголовке.

## Формат события

```json
{
  "token": "секрет",
  "serverId": "zaruba-1",
  "type": "ping",
  "ts": 1794863287,
  "data": {}
}
```

Каждое событие несёт `matchId` (serverId + время старта матча).

| type | data |
|---|---|
| `match_start` | `world` |
| `player_join` | `playerId`, `uid`, `name` |
| `player_leave` | `playerId`, `uid`, `name` |
| `player_spawn` | `playerId`, `uid`, `name`, `faction` |
| `kill` | `relation`, `teamKill`, `victim*` и `killer*` (`Id`, `Uid`, `Name`, `Type`, `Faction`), `weapon`, `weaponSource`, `damageType`, `hitZone`, `distance`, `pos` |
| `match_end` | `durationSec`, `endReason`, `winners` (ключи фракций) |

`kill` шлётся, если жертва или убийца — игрок. ИИ против ИИ не пишется.

## Подсчёт

- Засчитанное убийство: убийца — игрок, жертва — не он сам, не тимкилл. Боты считаются отдельно.
- Тимкилл: флаг `teamKill` от движка или отношение `*FRIENDLY*`. Движок ставит флаг только за
  союзника-игрока, поэтому убийство союзного бота определяется по отношению.
- Смерть: любая гибель игрока, включая самоубийство и тимкилл по нему.
- K/D = засчитанные убийства / смерти.
- Игрок определяется по ID игрока (> 0), а не по `victimType`/`killerType`:
  админ с правами GM приходит как `UNLIMITED_EDITOR`.
- Оружие (`weapon`, способ в `weaponSource`): мод запоминает последнее прямое попадание в персонажа
  (`OnDamage`, без кровотечения). Взрыв/осколки → боеприпас (`explosive`), наезд → машина (`vehicle`),
  стрелок в технике → техника (`vehicle`), пуля → оружие в руках (`hands`).
- Хедшот: зона последнего попадания `Head*` (`hitZone`).

## Идентификатор игрока

Ключ статистики — UUID игровой личности (постоянный). Ник хранится рядом и обновляется при каждом входе.

## Надёжность

- Каждое событие получает `eventId` (serverId + метка запуска + порядковый номер).
- До отправки мод пишет событие в `profile/ZarubaStats/outbox/<eventId>.json` и удаляет файл
  после ответа хоста. Если хост недоступен или сервер упал, файл остаётся.
- Буфер досылается при старте каждого матча и раз в 2 минуты.
- Хост пропускает событие с уже известным `eventId` и отвечает 200, чтобы мод удалил его из буфера.

## Этапы

1. Тест связи «мод → хост» (`ping`).
2. События игроков и убийств.
3. База SQLite и подсчёт статистики.
4. Discord: отчёт матча, `/stats`, таблица лидеров.
5. Команда `!stats` в игровом чате.
